# 项目目标与下一阶段计划

## 1. 总体目标

围绕赛题《多源异构数据驱动岗位和能力图谱构建与动态演化分析研究》，完成一套本地可运行的中文岗位分析与推荐系统：

```text
中文岗位 JD
-> BM25 倒排索引
-> 中文 Transformer Embedding
-> Neo4j 岗位能力图谱

用户简历
-> BM25 快速召回 Top200 岗位
-> 简历与候选岗位向量相似度排序
-> Neo4j 知识扩展与能力差距分析
-> 最终岗位推荐
```

当前不再以继续扩大采集量为首要任务，先使用已有数据跑通完整闭环。

## 2. 当前数据状态

| 国家公务员岗位 | 已完成，暂时够用 | 2026 年国家公务员岗位 20714 条，含招录机关、专业、学历、地点等结构化条件 |

## 3. 第一阶段：固定现有数据

### 3.1 岗位数据

第一阶段先使用以下两类岗位：

- 企业岗位：腾讯、华为部分公开 JD，共 3000 条。
- 公共部门岗位：2026 年国家公务员岗位，共 20714 条。

下一步只做统一字段、去重、文本清洗和质量抽查，不继续优先扩充企业数量。

### 3.2 中文简历数据分析

`Chinese_resume_data.csv` 和 `revise_Chinese_resume_data.csv` 均有 5000 条、34 个字段，主要特点如下：

- 覆盖 10 类技术岗位，包括前端、后端、全栈、算法、数据分析、数据工程、测试、运维、云计算和移动开发。
- 字段结构较完整，包含学历、专业、编程语言、技术栈熟练度、企业经历和项目规模。
- 带有“通过/不通过”筛选结果，可用于分类流程试跑。
- 大量专项技能字段缺失，符合简历技能稀疏的特点，但也会影响直接匹配。
- 两个中文文件主体数据相同，修订版仅调整了 2033 条筛选结果。
- 数据含姓名、电话、邮箱字段，正式实验前必须删除或匿名化。
- 目前没有“简历-JD 对应关系、相关性等级、技能实体边界、缺失能力”等细粒度人工标注。

因此，中文简历数据当前状态设为 **待定**：可用于系统联调和向量化实验，但暂不能作为人岗匹配效果的可靠金标准。

## 4. 第二阶段：本地化检索与推荐

这是下一阶段的核心主线。

### 4.1 岗位离线处理

```text
岗位 JD
-> 字段统一与文本清洗
-> BM25 构建倒排索引
-> Transformer 生成岗位 Embedding
-> 提取岗位、技能和能力关系
-> 写入 Neo4j
```

具体步骤：

1. 合并并标准化企业岗位与公务员岗位数据。
2. 使用岗位标题、JD、专业要求、学历要求和技能标签构建 BM25 倒排索引。
3. 使用适合中文的 Transformer Embedding 模型生成岗位向量并保存。
4. 从 JD 中抽取岗位、技能、能力、学历、专业和地区等实体及关系。
5. 将岗位能力关系写入本地 Neo4j。

### 4.2 简历在线查询

```text
用户简历
-> 脱敏、解析与技能提取
-> BM25 召回 Top200 岗位 JD
-> 生成简历 Embedding
-> 与 Top200 岗位向量计算相似度
-> 语义重排
-> 图谱扩展与规则重排
-> 最终 TopN 岗位推荐
```

BM25 的作用是快速缩小搜索范围，避免每次查询都让简历向量与全部岗位向量逐一计算。Transformer 只对 Top200 候选进行更精细的语义匹配和排序。

第一版综合分数可采用：

```text
最终分数 = BM25 分数 + 向量相似度 + 技能匹配度 + 条件匹配度 + 图谱扩展分数
```

各项分数先归一化，再通过实验确定权重。

### 4.3 Transformer Embedding 路线

原项目使用英文 Embedding，不适合当前中文岗位和简历数据，需要替换为中文或多语言模型。

分两步实施：

1. **直接使用现有模型**：先使用 `BAAI/bge-m3` 或 Qwen Embedding 完成岗位和简历向量化，快速建立可运行基线。
2. **领域微调**：在积累简历-岗位正负样本或相关性标注后，使用对比学习微调 Embedding 模型，使向量空间更符合中文招聘场景。

第一阶段不立即训练大模型。先验证现有模型效果，再根据 `Recall@200`、`NDCG@K` 和人工评测结果决定是否微调。

建议第一版使用：

- BM25：Elasticsearch/OpenSearch。
- 中文向量模型：优先测试 `BAAI/bge-m3`，并与 Qwen Embedding 做小样本对比。
- 向量存储：Elasticsearch `dense_vector` 或本地 FAISS。
- 第一版融合：BM25、向量、技能和条件分数归一化后加权。

阶段完成标准：岗位索引和向量库可本地重建，任意一份简历能通过 BM25 返回 Top200，经向量重排和图谱增强后输出最终 TopN 推荐及分数依据。

## 5. 第三阶段：Neo4j 岗位能力图谱

Transformer 能判断文本在语义上是否相似，但匹配过程较难解释。Neo4j 将“岗位需要哪些技能、简历具备哪些技能、还缺少哪些技能”明确表示出来，使推荐结果可解释，并补充纯文本检索无法发现的关联岗位。

### 5.1 图谱基本结构

- 节点：岗位、岗位族、技能、能力、企业/机关、行业、地区、学历、专业、时间。
- 关系：岗位需要技能、岗位属于岗位族、岗位来自组织、岗位位于地区、技能关联能力、岗位要求学历/专业。
- 关系属性：来源、出现次数、权重、首次出现时间、最近出现时间。

### 5.2 图谱的核心作用

1. **推荐解释**：说明某份简历为何匹配某岗位，列出共同技能、关键条件和关联能力。
2. **知识扩展**：从候选岗位沿“相似岗位、共享技能、所属岗位族”等关系扩展，发现 BM25 和向量检索未召回的相关岗位。
3. **能力差距分析**：对比简历技能集合与岗位必备技能集合，输出已具备技能、缺失技能和建议学习顺序。
4. **岗位演化分析**：记录技能关系在不同时间窗口中的频率和权重变化。
5. **新岗位发现**：识别无法归入现有岗位族、但具有稳定新技能组合的岗位簇。

图谱扩展得到的新岗位不能直接全部加入推荐结果，需要再经过技能覆盖、向量相似度和岗位条件过滤，防止关系扩展带来无关候选。

### 5.3 新岗位发现与定义

简单实现路径：

1. 对岗位标题和 JD 生成向量并聚类。
2. 找出无法稳定归入既有岗位族的岗位簇。
3. 分析该簇高频且有区分度的技能组合。
4. 结合多来源岗位数量和时间持续性，生成候选新岗位及其能力定义。
5. 经人工确认后写入 Neo4j。

### 5.4 既有岗位能力动态更新

按月或季度统计岗位技能变化，识别：

- 新增能力：过去较少、当前持续出现。
- 上升能力：出现频率或重要度明显增加。
- 稳定能力：长期保持核心地位。
- 下降能力：频率持续降低。

将统计结果写入图谱关系的时间、频次和权重属性，形成岗位能力演化记录。

## 6. 第四阶段：人岗匹配与差距分析

基于 BM25 召回的 Top200 候选岗位，综合以下信息完成重排：

- 语义相似度与 BM25 相关度。
- 技能覆盖率和核心技能匹配度。
- 学历、专业、经验、地区等条件约束。
- 图谱中的岗位族、关联技能和相邻岗位信息。

例如用户只掌握 Python，而目标岗位还要求 SQL、机器学习框架和数据工程能力时，系统不能只输出“匹配”或“不匹配”，而应给出当前匹配程度、关键缺口以及从现有能力到目标岗位的补充路径。

最终输出：

- 推荐岗位及综合分数。
- 已满足的核心能力。
- 缺失或薄弱能力。
- 可迁移的相邻岗位。
- 建议优先补充的技能和学习方向。

## 7. 评测与人工标注

现有“通过/不通过”不能替代检索评测标注。后续从岗位和简历中抽取小规模人工评测集，至少标注：

- 简历与岗位的相关性等级。
- 必备技能、加分技能和缺失技能。
- 岗位所属岗位族。
- 新岗位候选是否成立。

主要指标使用 `Recall@200`、`HitRate@K`、`NDCG@K`，并抽查推荐解释、图谱扩展和能力差距结果是否合理。

## 8. 最近执行顺序

1. 合并 3000 条企业岗位和 20714 条公务员岗位，形成统一岗位主表。
2. 对中文简历脱敏，确定使用原版还是修订版，状态暂保持待定。
3. 构建 BM25 索引并完成岗位检索测试。
4. 生成岗位向量并建立本地向量库。
5. 向量化简历，对 BM25 Top200 候选计算相似度并重排。
6. 构建 Neo4j 最小图谱，加入推荐解释、知识扩展和能力差距分析。
7. 在基线效果稳定后，准备简历-岗位标注样本并评估是否微调 Embedding 模型。
8. 加入新岗位发现与既有岗位能力动态更新原型。
