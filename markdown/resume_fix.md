# 中文简历处理、标注与基准测试方案

## 1. 目标

基于现有中文简历和统一岗位主表，建立一套能够评测以下环节的中文人岗匹配基准：

```text
简历解析
-> BM25 召回 Top200
-> 中文 Embedding 语义重排
-> Neo4j 技能扩展
-> 多因素人岗匹配
-> 推荐解释与能力差距分析
```

本方案参考论文《An Intelligent Job Matching Platform Using Knowledge Graphs, Semantic Search and Explainable AI》。论文的关键经验是：自动生成的银标可以用于开发，但正式指标必须使用独立人工标注的金标，避免用同一套技能规则生成标签并评测同一套技能匹配方法。

## 2. 当前中文简历数据判断

`dataset/resume/` 中两个中文 CSV 均包含 5000 条简历、34 个字段和 10 类技术岗位。

### 可利用部分

- 已有意向岗位、学历、专业、英语水平、技能、技能熟练度、企业经历和项目规模等结构化字段。
- “通过/不通过”可作为辅助分类标签，帮助检查基础筛选流程。
- 结构化字段适合快速生成简历文本、技能集合和简历向量。

### 当前问题

- 没有简历与具体 JD 的对应关系，不能直接评测岗位排序。
- 没有相关性等级、必备技能、加分技能和能力缺口标注。
- 原版与修订版仅“筛选结果”有 2033 条差异，修订版正负样本被调整为 2500:2500，标签来源和修改规则需要核查。
- 大量专项技能字段为空，空值只能表示“未填写或不具备”，不能直接当作确定的负技能。
- 数据含姓名、电话和邮箱，必须脱敏。
- 数据高度结构化且分布较规则，需核查是否为合成数据，不能直接代表真实中文简历分布。

结论：现有中文简历可用于流程联调和银标开发集，但不能直接作为最终人岗匹配金标测试集。

## 3. 简历数据处理方案

### 3.1 保留原始数据

- 原始文件只读保存，不在原文件上修改。
- 为每条简历生成稳定 `resume_id`。
- 记录数据版本、处理时间和来源文件。
- 原版和修订版都保留，通过 `label_version` 区分。

### 3.2 脱敏

删除或散列以下字段：

- 姓名。
- 电话。
- 邮箱。
- 其他能够直接识别个人身份的信息。

年龄、性别不进入第一版推荐分数，防止模型产生不必要的招聘偏差；它们仅可用于后续公平性检查。

### 3.3 统一简历结构

建议形成以下标准字段：

| 字段 | 用途 |
| --- | --- |
| `resume_id` | 简历唯一标识 |
| `target_job_family` | 意向岗位族 |
| `education` | 学历层次 |
| `major` | 专业类别 |
| `experience` | 企业经历和经验水平 |
| `projects` | 项目规模与项目经历 |
| `skills_raw` | 原始技能字段 |
| `skills_normalized` | 归一化技能列表 |
| `skill_levels` | 技能熟练度 |
| `profile_text` | 用于 BM25 和 Embedding 的完整简历文本 |
| `screening_label` | 原始通过/不通过标签，仅作辅助任务 |

`profile_text` 不应只是技能拼接，应包含意向岗位、学历、专业、经验、项目和技能等完整信息。

### 3.4 技能标准化

建立中文技能词表和别名表，例如：

```text
PyTorch / torch -> PyTorch
大语言模型 / LLM / 大模型 -> Large Language Model
容器编排 / Kubernetes / K8s -> Kubernetes
```

技能标准化结果同时用于：

- BM25 字段增强。
- Embedding 文本构造。
- Neo4j `HAS_SKILL` 和 `REQUIRES_SKILL` 关系。
- 能力差距分析。

## 4. 标注体系

标注分成银标和金标，两者用途必须分开。

### 4.1 银标：用于训练和开发

银标可由规则自动生成：

- 意向岗位与岗位族一致。
- 简历技能与 JD 技能有一定重合。
- 学历、专业和经验满足基本要求。
- BM25、Embedding 或图谱检索进入候选集合。

建议银标相关性分数：

```text
silver_score = 岗位族一致性 + 技能覆盖率 + 条件满足度 + 语义相似度
```

银标可以用于构造正负样本、模型微调和错误分析，但不能作为最终测试集的唯一真值。

### 4.2 金标：用于正式基准测试

从统一岗位主表中为每份待标注简历抽取候选岗位：

- BM25 高排名岗位。
- Embedding 高排名岗位。
- Neo4j 扩展岗位。
- 相似但缺少关键技能的困难负样本。
- 少量随机负样本。

人工对每个“简历-岗位”对标注四级相关性：

| 等级 | 含义 |
| --- | --- |
| 3 | 高度匹配，核心技能与主要条件基本满足 |
| 2 | 可以推荐，但存在少量可补足的能力缺口 |
| 1 | 岗位方向相关，但存在明显技能或硬条件差距 |
| 0 | 不相关或不满足关键硬条件 |

另外独立标注：

- `hard_constraint_pass`：学历、专业、经验等硬条件是否通过。
- `matched_skills`：已满足的岗位技能。
- `missing_required_skills`：缺失的必备技能。
- `missing_optional_skills`：缺失的加分技能。
- `transferable_skills`：可以迁移到该岗位的相近技能。
- `evidence`：支持判断的简历字段和 JD 原文片段。

### 4.3 标注质量控制

- 每个样本由两名标注者独立完成。
- 分歧样本由第三人仲裁。
- 使用加权 Cohen's Kappa 检查四级相关性一致性。
- 第一版目标为 Kappa 不低于 0.80，参考论文可将 0.85 作为理想值。
- 标注者只能查看简历与 JD，不查看 BM25、Embedding 或图谱给出的最终分数。

## 5. 基准数据集设计

### 5.1 第一版规模

建议分两步建设：

1. 试标阶段：30 份简历，每份约 20 个候选岗位，共约 600 个简历-岗位对。
2. 正式第一版：100 份简历，每份约 20 个候选岗位，共约 2000 个金标样本。

其余 5000 条简历可以生成银标，用于训练、微调和大规模诊断。

### 5.2 数据划分

训练集、验证集和测试集建议按 60%/20%/20% 划分，并同时满足：

- 同一 `resume_id` 不能跨集合。
- 高度重复的简历不能跨集合。
- 高度重复的 JD 不能跨集合。
- 测试集保留部分训练阶段未出现的技能簇，形成类似论文的 skill-disjoint 测试。
- 单独设置企业岗位测试和公务员岗位测试，避免两类岗位条件差异被平均指标掩盖。

## 6. 基准任务与指标

### 6.1 简历解析

评测技能、学历、专业、经验和岗位意向的抽取效果：

- Precision。
- Recall。
- F1。
- 技能标准化准确率。

### 6.2 BM25 候选召回

验证相关岗位是否进入候选集：

- `Recall@50`。
- `Recall@100`。
- `Recall@200`。
- P50/P95 查询延迟。

这一阶段重点看召回率，不追求最终排序精度。

### 6.3 Embedding 重排

对 BM25 Top200 进行中文向量相似度重排，评测：

- `NDCG@5`、`NDCG@10`。
- `MRR`。
- `HitRate@5`、`HitRate@10`。

对比模型至少包括：

- 原项目英文 Embedding。
- `BAAI/bge-m3`。
- Qwen Embedding。
- 领域微调后的中文 Embedding。

### 6.4 Neo4j 图谱扩展

评测图谱是否真正补充了 BM25 和 Embedding 未找到的岗位：

- 图谱新增候选数量。
- 新增候选人工相关率。
- 技能同义词和关联技能召回率。
- 扩展前后 `Recall@200`、`NDCG@10` 的变化。
- 无关扩展率，检查知识扩展是否发生主题漂移。

### 6.5 能力差距和解释

参考论文，将解释限制在已计算分数和图谱证据上，不允许生成模型自行创造匹配理由。

人工检查：

- 是否提到最主要的匹配因素。
- 是否指出低于阈值的弱项。
- 是否正确列出缺失的必备技能。
- 是否存在无证据的技能或结论。
- 用户对 Top5 相关性和解释帮助度的 1-5 分评价。

## 7. 必须完成的消融实验

依次比较：

1. 仅 BM25。
2. 仅中文 Embedding。
3. BM25 + Embedding 重排。
4. BM25 + Embedding + Neo4j 扩展。
5. BM25 + Embedding + Neo4j + 多因素重排。

只有这样才能说明每个模块是否真正带来提升，而不是只展示完整系统的一个最终分数。

## 8. 多因素重排建议

参考论文，第一版可以采用透明的白盒评分：

```text
总分 =
0.35 * 技能匹配
+ 0.25 * 经验匹配
+ 0.15 * 地区匹配
+ 0.10 * 学历/专业匹配
+ 0.10 * 语义相似度
+ 0.05 * 岗位族或组织偏好
```

企业岗位和公务员岗位应使用不同权重。公务员岗位中的专业、学历、政治面貌等通常属于硬条件，应先过滤，再参与排序；企业岗位可更多依赖技能、经验和语义相似度。

## 9. 风险与边界

- “通过/不通过”不能直接等同于具体岗位的相关性。
- 银标不能用于报告最终测试指标，否则会产生评测循环。
- 不使用姓名、性别、电话、邮箱等信息参与推荐。
- 需要单独检查不同学历、经验和非传统职业路径群体的效果差异。
- 推荐分数表示与特定 JD 的相关程度，不表示候选人的总体价值，也不能代替人工招聘决策。

## 10. 建议执行顺序

1. 对 5000 条中文简历完成脱敏和统一结构转换。
2. 建立技能标准词表、别名表和岗位族映射表。
3. 从 30 份简历开始试标 600 个简历-岗位对。
4. 修订标注规范并检查双人标注一致性。
5. 扩展到约 2000 个独立金标样本。
6. 跑通 BM25 `Recall@200` 基线。
7. 对比 `bge-m3`、Qwen Embedding 和原英文模型的重排效果。
8. 加入 Neo4j 后完成消融实验和能力差距解释评测。
